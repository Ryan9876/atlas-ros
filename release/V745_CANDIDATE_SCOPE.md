# Atlas ROS v7.4.5 Candidate Scope

## Status

Non-publishing candidate development. Production authority remains Atlas ROS v7.4.0 with v7.3.0 as immediate rollback.

## Included capabilities

1. Per-operation immutable read snapshots.
2. Provider read planning and request coalescing.
3. Precompiled verified registry bundles.
4. Governed performance contracts and telemetry.
5. Capability-scoped runtime composition.
6. Incremental content-addressed operational computation.

## Explicit exclusions

- No incremental pipeline or stage digest optimization.
- No concurrent, parallel, worker-pool, or asynchronous runtime processing.
- No resident daemon, attended warm session, cross-command connection pooling, or retained authorization.

## Compatibility and safety

The candidate preserves GitHub-first authority initialization, canonical coordinator ownership, adapter boundaries, exact authorization, pre-write validation, mandatory provider readback, reconciliation boundaries, command semantics, cold execution, full composition, full recomputation, deterministic output, and Active and rollback restoration.

Optimization artifacts are non-authoritative and disposable or immutable package-bound according to their classification. No production schema migration is required or authorized.

## Completion boundary

Candidate preparation may create code, tests, documentation, build-once artifacts, checksums, SBOM, source manifest, validation evidence, restoration evidence, and a draft pull request. It must stop before merge, publication, tag creation, release creation, authority activation, Notion System State changes, integration-scope changes, credentials, deletions, messaging, calendars, scheduling, Todoist writes, or live provider migrations.
