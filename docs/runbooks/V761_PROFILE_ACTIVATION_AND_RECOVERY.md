# Atlas ROS v7.6.1 Profile Activation and Recovery Plan

## Preconditions

1. Re-read canonical GitHub authority, Release Index, immutable manifest, Notion System State, and Integration Inventory.
2. Verify v7.6.1 was published from the exact retained build without rebuilding and independently read back.
3. Verify canonical authority identifies v7.6.1 Active and v7.6.0 immediate rollback.
4. Verify the exact minimized profile bundle was separately authorized by Ryan.

## Activation transaction

1. Validate exact user ID, workspace ID, repository binding, profile version, digest, review date, entry counts, and exact global enable state.
2. Read back the governed evidence references and confirmation states.
3. Install the exact access-controlled bundle without placing it in package or public repository state.
4. Read back bundle identity and digest.
5. Apply only the exact authorized feature-policy target.
6. Verify current-instruction override, privacy redaction, deterministic adaptation, consequential clarification, and zero provider authority.
7. Record final cross-authority and profile readback.

## Disable and rollback

- Global disable: set the profile feature to disabled and read back immediately.
- Profile rollback: select the previously authorized profile version or remove the active binding; fall back to v7.6.0 behavior.
- Software rollback: restore v7.6.0 using the immutable rollback package identified by live authority.
- Do not delete governed evidence or user-control history during disable or rollback.

## Fail-closed triggers

Identity mismatch, digest mismatch, expired review, missing evidence, open contradiction, permission change, provider-write evidence, or authority disagreement blocks activation and preserves the disabled baseline.
